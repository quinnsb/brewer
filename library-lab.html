Library Lab

Three renderers over one data file. Every shelf below reads data/library.json, built by tools/library-sync.mjs from keyless public sources, with palettes extracted by tools/library-colors.mjs. Twenty-eight real items with real cover art.

Four media types, four physics. Books stand as spines because book spines are designed to be read on a shelf. Albums do not: a vinyl spine is blank card, so they lean forward in a crate you flip through. Films sit in a poster rack. Podcasts tile, because there is no physical object worth faking. Toggle the spine labels to see the fallback for anything whose art is missing or unreadable at sliver width.

Deliberately simplified. One mesh per item, cover art on the front face, palette colour on the sides, damped virtual scroll, raycast picking. Scroll to move along the shelf, click a volume to pull it out. For scale: complete-shelf runs roughly 2,200 lines and side-one runs 11,433, both for seven items. This is a few hundred for twenty-eight, so judge the feel, not the finish.

Content tiering and render tiering as one decision. You said full writeups for a starred few and metadata for the rest. This mirrors that in the rendering: starred items get presence and space, everything else packs into a dense browsable shelf. Nothing is arbitrary because both tiers come from the same editorial call.
